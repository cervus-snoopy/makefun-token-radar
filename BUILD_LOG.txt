## Approach — radar-2, not the starter's flat multiple

The starter scores TVL x 0.25 x growth x maturity. This entry scores every row
with one function built only from the snapshot's own figures, no hardcoded names:

  implied = TVL x comps x growth x maturity x chains
  comps    = median(market cap / TVL) of the live protocols in the row's own
             category, clamped to [0.05, 1.00]; fewer than 3 live peers uses
             the whole market's median (0.169)
  growth   = 1 + clamp(7d change, -60%, +120%) x 0.6
  maturity = 0.6 + min(age, 1460 days) / 1460 x 0.4 (age unknown: 365)
  chains   = 1 + 0.03 x min(chains - 1, 5)

The board holds EVERY rankable pre-token protocol: the whole 40-slug watchlist
(the floor, never the ceiling) plus every other rankable pre-token protocol
below the floor — 198 rows, not a 200-row sample. A separate readiness score
(0-100, display only: 40% age, 30% growth, 30% size) says how close a launch
looks; the rank always follows the implied value.

## What "rankable" means — the fix that mattered

First build ranked 289 rows, topped by coinbase-bridge, wbtc, binance-bitcoin,
usdt0 and base-bridge — bridged/wrapped products, exactly what the house's
watchlist definition excludes. isRankable now applies the watchlist's own
exclusion logic to every board row:

- category in Bridge / Canonical Bridge / Liquid Staking / Liquid Restaking /
  Restaked BTC / CEX — never ranked
- name has a whole word wrapped / staked / staking
- name ends in a version marker (V2, v1, 2.0 — "Rysk V12" caught by the
  stricter regex; the check script's looser pattern missed it)
- name begins with an exchange name, derived at run time from the snapshot's
  own CEX protocols (first word of each CEX name); verified: it never fires
  alone in this snapshot, so it cannot over-exclude
- watchlist re-checked under the new rules: 0 failures, no coverage conflict

from the protocol's own category / chains / TVL / age — fresh wallet, the
category's one action sized by TVL ($50/$100/$150/$250), a weekly qualifying
action, a hold window sized by age (30/45/60 days), a points check from the
protocol's own page, a farm log.
